### 前言
##### AGU 旗下期刊对“开放数据（Open Data）”的审查已达到前所未有的严格高度，过去那句“数据可向通讯作者索取”的时代已经一去不返。现在，所有支撑文章图表和核心结论的数值模拟数据，都必须在发表前托管至符合FAIR（可发现、可访问、可交互、可重用）原则的公开数据库中。我们在此介绍如何将大数据（本文上传数据41G）上传到Zenode上。
---

### 1.[Zenodo](https://zenodo.org/)数据托管

![Zenodo logo (来自官网)](https://openscience.cern/sites/default/files/2023-07/banner_1.png)


作为由欧洲核子研究组织（CERN）开发、欧盟大力支持的全球顶级学术开源仓储，它堪称科研界的数据托管天花板，具备以下硬核福利：
---
- 完全免费且容量惊人：对全球科研人员免费开放，不收任何托管费，单文件上传上限直接拉满到 **50GB**！
- 自带永久“身份牌”（`DOI`）：上传后系统会自动分配国际公认的 `DOI`，让你的数据集变成可被正式引用的学术资产。
- 无缝对接 `Python` 生态：数据保持原始格式，全球同行可无缝下载并直接用 `xarray` 和 `pandas` 进行读取分析，极大促进学术协作。

### 2.如何上传大数据
如果数据较小，可直接从本地电脑拖拽至Zenodo上，我们这里针对的是大数据，即数据压缩后仍超过10G以上。

#### 2.1 获取Zenodo令牌（`Token`）
1. 登录自身Zenodo账号。
2. 进入 `Applications` -> `Personal access tokens`。
3. 新建一个 `Token`，勾选 `deposit:write` 和 `deposit:actions` 权限，生成后将其复制保存下来。
4. 在 Linux 终端中，将这个 `Token` 存入环境变量（防止之后反复输入）：
```
 export ZENODO_TOKEN="你的Token"
```
#### 2.2 Zenodo创建项目
1.在浏览器中打开 Zenodo 并点击 `New upload`。
2.填写最基础的必填元数据（如 `Title`、`Authors`、`Description`），然后点击页面上方的 `Save draft`（先不要在网页端上传任何文件）。  观察此时浏览器的 URL 地址，长得像https://zenodo.org/records/1234567, 或者包含 /deposit/1234567，这一串数字（例如 `1234567`）就是你的 `Deposition ID`。
3.在 Linux 终端中，将此 ID 同样存入变量：  
```
 export DEPOSIT_ID="你的DepositionID"
```

#### 2.3 初始化文件槽
告诉系统要传文件,运行后会返回一串包含文件状态为 pending 的 JSON，说明槽位创建成功.
```
curl -X POST -H "Authorization: Bearer $ZENODO_TOKEN" \
     -H "Content-Type: application/json" \
     -d "[{\"key\": \"archive.tar.gz\"}]" \
     "https://zenodo.org/api/records/$DEPOSIT_ID/draft/files"
```

#### 2.4 后台流式上传
改用二进制流，绕过 Nginx 限制,这一步最耗时，你可以像之前一样用 `tail -f re_upload.log` 来监控进度。
```
nohup curl -X PUT \
     -H "Authorization: Bearer $ZENODO_TOKEN" \
     -H "Content-Type: application/octet-stream" \
     -# --upload-file "./archive.tar.gz" \
     "https://zenodo.org/api/records/$DEPOSIT_ID/draft/files/archive.tar.gz/content" > re_upload.log 2>&1 &
```

#### 2.5 提交确认
当大文件彻底传完（re_upload.log 进度走到 100% 且 curl 进程结束）后，必须运行最后这一条命令告诉 Zenodo 传输已合并完成，否则网页端会一直显示文件正在处理中：
```
curl -X POST -H "Authorization: Bearer $ZENODO_TOKEN" \
     "https://zenodo.org/api/records/$DEPOSIT_ID/draft/files/archive.tar.gz/commit"
```
通过这一套分步流式的组合拳，**41GB** 的大文件就能顺利绕过413门槛安全上岸了！

--------------
### 小贴士：
- 文件名必须严格对齐：步骤 2.4、2.5、2.6 中的 archive.tar.gz 必须完全一致。如果你上传的是别的文件，记得三处一起修改，否则新版 API 无法精准对齐槽位。

-  Zenodo 为了保证学术引用的严肃性，一旦点击 `Publish`，已经上传的 41G 核心数据包（`Data File`）就会被永久锁定，无法在当前版本中删除或替换。如果后续数据确实有重大更新，只能通过页面上的 `New version` 功能生成一个新的 `DOI` 版本。

- 元数据（`Metadata`）随时可免费修改：虽然数据包锁定了，但是数据集的标题（`Title`）、描述（`Description`）、作者信息等元数据，在发布后依然允许随时修改且实时生效！ 只需要登录网页端，找到该条目并点击右上角的 `Edit metadata`，润色完学术语言后点击 `Save and Publish` 即可，这完全不会影响你已经生成的永久 `DOI`。
